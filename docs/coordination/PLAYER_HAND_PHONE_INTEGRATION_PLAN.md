## User flow

1. Add a separate text action 'Player hand positions' in match detail near saved fusion status, not replace the existing match JSON download or fusion export. Available only with match-owned saved fusion; absent source gives 'Save fusion evidence for this game first.' No log reader/recollection/upload required.
2. Load/decode the owned artifact in background through FusionImportRepository.artifactForExport(matchId) and FusionArtifactCodec, not arbitrary journal paths. Retain one immutable decoded artifact for the dialog/session. Display existing saved-result consistency warning for historical fusion; report describes that preserved artifact, not necessarily current edited match result. Pin content hash/revision for preparation and export; do not silently switch to another artifact if import changes.
3. Select one checkpoint explicitly. Use a lazily displayed list/filter and exact checkpoint ID, not inferred turn matching. Each entry shows epoch, raw turn/UNKNOWN, phase and source line; expandable technical details show source/ID. Friendly label for BEFORE_ACTION: 'Before logged action — not a verified decision-time view.' Do not select nearest/latest automatically or merge duplicate checkpoint IDs. A checkpoint rejected by core validation is unavailable with a reason, not fallback.
4. Explicitly select the side to treat as player. No default, turn-parity guess or automatic candidate-controller verification. Plain-language prompt: 'Choose the side to show as your hand. The app has not verified which side is yours.' Side options identify numeric controller under details; no guessed class/alias. May show bounded position-only previews for user orientation, not claimed identity evidence. Controller list comes from positive observed hand-owner data at the checkpoint, deduplicated; unknown/absent owner offers manual positive numeric selection with clear limitation, not fabricated slots. Reuse core projection for previews, no separate position engine. Selection remains an annotation, scoped to artifact/checkpoint, not written back as verified observer.
5. Preview a single player's observed slots in order with source details expandable. Plain-language banner: 'Some cards may be missing from this record. Card names and costs are not included.' Gaps/duplicates remain visibly qualified; never renumber or invent filler slots. 'No recorded hand positions at this point' does not mean empty hand. Opponent output absent/nonblocking.
6. 'Save report' opens CreateDocument(text/plain), with UTF-8 plain-text contents from the reviewed renderer. Its Markdown-style headings/escaped data are readable text, not executable WebView/HTML. Suggested filename uses only sanitized bounded ASCII tokens: player-hand_<match-token>_r<artifact-revision>_e<epoch>_<checkpoint-token>_c<controller>_<hash-prefix>.txt. No raw checkpoint/path string in filename. Include exact artifact identity in preview/session metadata; report already contains match/revision/checkpoint provenance. No new fusion schema or auto-export setting.

## Execution and lifecycle contract

One active job/session, disable repeated generation/save, background decode/render and cancellation callback from coroutine ensureActive. Use existing renderer bound65536 chars; overflow reports 'This checkpoint report is too large; no report was saved' rather than truncate warnings. Artifact decode/input size must use an explicit existing/import-compatible limit or an approved bounded-reader helper; do not introduce unbounded readText for arbitrary size or claim the output bound limits decode memory. Establish exact input cap with existing artifact size evidence/tests at implementation, without silently excluding supported captures. No whole-game materialization loop/bulk export.

Generate immutable report payload before launching picker. Keep necessary pending payload across picker pause/resume without continuing log collection, using a small lifecycle-safe state holder/unique private temporary file if needed; no stateful guessing after process death. Cancellation/recreation missing payload displays a retryable message, never success. Do not cancel merely because the system save picker pauses the screen; cancel abandoned generation on dialog disposal. Process death can safely require regeneration; no automatic re-export. Do not persist private report in saved-state bundles. Any owned temporary file has scoped cleanup on cancellation/completion/restart, separate from preserved fusion/raw evidence.

On URI cancellation: 'Save cancelled. Your game data is unchanged.' On successful write/close: 'Report saved to the location you chose. Cloud upload is not confirmed.' IO/cancellation failure: detailed troubleshooting message and 'The destination may contain an incomplete file'; never overwrite/delete the original fusion or claim remote arrival. Do not remove provider documents blindly. No default Drive folder or cloud uploader. The user's Development APK packaging rule is unrelated to report destinations.
